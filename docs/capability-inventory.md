# 公开测试版能力清单 — Search Hub v0.1.2

日期：2026-11-14 ｜ 基线：`418d428` + 本轮远端验收准备提交
判定口径：**只有真实外部调用才算「真实联调通过」**。Mock、契约测试、本地模拟服务一律只算「模拟测试通过」。

## 1. 状态定义

| 状态 | 含义 | 可否对外写「支持」 |
|---|---|---|
| **真实联调通过** | 有真实网络请求、真实第三方响应、真实 URL 的记录 | 可以，且必须注明版本与日期 |
| **模拟测试通过** | Mock/契约/本地模拟服务证明协议与控制流，未接触真实服务 | 只能写「按官方文档实现，未联调」 |
| **接口健康已知** | 只探测到端点在线与鉴权错误（如 401），没有拿到真实结果 | 不能写「可用」，只能写「端点可达」 |
| **尚未验证** | 没有可复现证据 | 不能写入能力清单 |

## 8. 可以直接对外说 / 不能说的话

**可以说**

- 「自托管的多源搜索聚合服务，REST 与 MCP 双协议，Hacker News 已真实联调。」
- 「7 个适配器已实现；Tavily / 博查 / Brave / SearXNG 按官方文档实现，尚未完成真实联调。」
- 「397 个自动化测试通过（本地与 CI 配置），Docker 镜像与容器验收待首次远端执行。」

**不能说**

- 「支持 29 个搜索源」——实际是 8 个适配器 + 21 条目录条目。
- 「通用网页搜索已验证」——只有 HN 一个垂直源。
- ~~「Docker 部署已验证」~~——现已可写「Docker 镜像与容器验收已在 GitHub Actions 通过」，但仍不能写「生产就绪」。
- 「生产就绪 / production-ready」——AC-05、容器、真实 Provider 均未达标。
